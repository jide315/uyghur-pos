# 阶段目标与验收清单

更新日期：2026-11-13；计划版本：v0.2。

本文件是阶段顺序、交付物和通过条件的主入口；实验口径以 [评测与决策协议](05-evaluation-protocol.md) 为准。原 [实验计划](02-experiment-plan.md) 保留方法和预算背景。若旧文档较宽泛，以本次明确的阶段规则为准。

**以下状态是方案制定时的快照。** 当前执行状态与证据以 [执行管理](../EXECUTION.md) 和 [进度索引](../../reports/README.md) 为准，不能把快照中的“未开始”当成现在没有执行。

## 1. 总目标及完成的含义

主题保持为：面向 CPU 部署的轻量维吾尔语词性标注。

完整实验路线：公开数据准入 → 可比基线 → 学生模型 → 错误观察 → 针对性改进 → 最终评测 → 可复现交付 → 开源与求职材料。

分别判断三个结果，不混为一谈：

- **工程交付完成**：可复现的代码、模型（许可允许时）、报告和使用入口齐全；失败实验也可完成交付。
- **压缩目标达成**：达到预注册的质量与资源门槛，不能用“代码能跑”代替。
- **社区价值获得验证**：有实际复用、独立复现反馈或上游采用证据；仓库公开不自动等于社区价值已验证。

本方案最初制定任务仅完善文档；用户随后已授权连接已有 AutoDL、实现并持续完成既定目标。当前在现有实例与已知预算条件下执行，实际公开发布、对外消息和社区采用仍分别记录。

## 3. P0：边界与资源约定

### 目标

把“做一个小模型”变成输入输出、目标和资源都明确的实验。

### 交付物

未来 `reports/P0-scope.md`：记录任务定义、预计使用者、未知项、预算状态、主资源指标和计划版本。

### 验收标准

- 明确任务为已分词句子的 UPOS 标注，未包含分词、ASR 或 OCR。
- 首版输入约定为 UTF-8 JSONL，每行 `{"tokens": ["词1", "词2"]}`；输出保留原词并增加等长 `upos` 列表，具体错误行为见 P7。
- 用户已明确的信息与方案假设分开记录；岗位、语言能力、精确预算未回答时写“未知”，不虚构。
- 暂按 400 元规划；实际授权支出上限未确定时，不启动新付费运行。
- 接受本协议作为预注册候选；P2 后、正式训练前允许一次有理由的参数／门槛修订，并保留旧版。

### 未通过处理

精确预算未知不阻止免费的数据与基线准备；需要付费时才受该缺失约束。若目标岗位变为语音或视觉，先更新路径决策，再进入训练。

## 4. P1：数据准入与评测器

### 目标

确保数据、词边界和指标足以支持可信比较。

### 交付物

未来 `reports/P1-data-audit.md`、`artifacts/data-manifest.json`、数据准备与评测脚本及必要的解析／指标测试。

### 验收标准

- 记录 UD 仓库、release 或 commit、原始文件 SHA-256、各切分句数与实际评测词数。
- 对所有整数 ID 的词记录读取 FORM／UPOS；区间 ID、多词记录和小数 ID 空节点不当普通词评测；句子、词顺序不变。
- 无无法解释的解析失败、丢词或缺失标签；异常逐条定位，不静默过滤。
- 完全匹配预测准确率为 100%；故意改错一个标签得到正确的错误计数；长度不匹配直接报错。
- 统计跨切分完全重复与规范化后重复，近重复采用记录阈值的诊断方法；不以此擅改官方切分。
- 词表、频次、字符表和分组阈值只根据训练集构建，未知字符有显式后备处理。
- 数据、模型及依赖许可分别列出；当前可做什么、发布前仍需核查什么写清楚。

### 未通过处理

修好解析、对齐或缺失来源问题再继续。测试集只允许结构与泄漏检查，不输出用于模型选择的测试分数。

## 5. P2：强基线与贡献空间

### 目标

先知道已有模型做到什么，再判断压缩是否值得投入。

### 交付物

未来 `reports/P2-baseline.md`、基线开发集预测、质量与资源原始测量、环境与模型清单。

### 验收标准

- 固定 Stanza 包、资源、权重及训练数据版本；核对训练来源，不能让使用过测试数据的教师参与比较。
- 若预训练模型来源不足以确认干净评测，明确该限制；必要时按官方训练切分重新训练可比教师，先重新估算预算，不能默认公平。
- 只启用词性标注所需组件和资源；输入预分词，输出逐词严格对齐。
- 两次独立进程运行的开发集预测一致；若存在非确定性，定位并报告。
- 按协议保存开发集 UPOS、非标点、OOV、分组统计及 CPU 时延、内存和体积。
- 不将本地金标准分词分数与官网端到端分数直接判优；版本或口径不同的差异有解释。
- 对至少一种具体约束提出可测的理由，例如目标 CPU 内存／延迟限制；该约束须在继续报告中写出数值及依据，不能只写“越小越好”。
- 输出 `GO`、`REWORK` 或 `STOP`。`GO` 必须包含可比基线、压缩机会假设、验证方法和预算估计。

### 未通过处理

没有可靠基线则先修复评测；没有贡献空间则停止压缩，保留复现报告。转向上游修复必须有独立可复现问题，不能以换题回避失败。

## 6. P3：本地与 AutoDL 执行准备

### 目标

让训练可追踪、可恢复、可回收产物，避免按 SSH 会话生命周期保存实验。

### 交付物

未来 `reports/P3-environment.md`、不含秘密的环境清单、运行／恢复／结果同步说明和费用台账。

### 验收标准

- 若本地 CPU 已足够，记录本地路径并跳过远端项；训练使用 GPU 不作为成果成立的必要条件。
- 使用 AutoDL 时，先收到 SSH 参数并验证网络、认证、GPU、Python、磁盘与可用空间；目前尚无连接参数，不视为已接入。
- 代码以本地 `/root/src/uyghur-nlp/` 为主，远端使用确认后的项目目录；平台盘符和持久性先验证再决定数据／checkpoint 位置。
- 本地与远端记录同一源码版本或源码包哈希；同步显式排除凭据及无关文件。
- 用不涉及正式训练的小型任务验证后台运行：断开并重新连接后任务、日志、退出码可查；保存的样例 checkpoint 可加载，产物可传回并校验 SHA-256。
- GPU 场景执行一次小张量／短批次试跑，记录显存、时间、GPU 数量，确认单卡可运行。
- 记录实际小时单价、计费起止、存储成本和剩余预算；预计下一次运行成本必须包含 25% 余量。

### 未通过处理

远端不可达时可继续本地开发，但不启动远端正式运行。日志／产物位置不可靠时先解决保存与恢复。只有已有授权预算覆盖计划运行时才进入付费训练。

## 7. P4：监督学生基线

### 目标

建立可训练、可加载、可公平比较的小模型，验证模型与数据管道正确性。

### 交付物

未来 `reports/P4-student.md`、训练配置、日志、checkpoint、开发集预测及资源数据。

### 验收标准

- 模型为字符编码＋小型 BiLSTM＋UPOS 分类层；结构、参数量、字符和词嵌入策略有记录。
- 在不超过 32 个训练句的小样本上，训练准确率达到 98%（或先解释冲突标注），作为管道检查；不将该分数当泛化结果。
- loss 有限，无 NaN／Inf；padding 不参与损失及指标，未知词和未知字符输入不崩溃。
- 保存前后 CPU 加载得到相同预测；原始词及数量完全保留。
- 完成一个监督配置的开发集结果；早停、最佳 checkpoint 和容量选择仅用开发集。
- 词典／多数标签基线仅用于诊断。若学生未超过简单基线，或总体比 Stanza 低 5 个百分点以上，先定位问题；最多一次有依据的容量调整再决定是否继续。

### 未通过处理

管道检查失败先修实现，不进入蒸馏。质量较差时先查对齐、损失、数据量、词表及未知字符，再考虑结构；不能直接增加更多实验掩盖问题。

## 8. P5：错误观察与针对性改进

### 目标

交付一个能解释的“失败观察 → 假设 → 干预 → 测量”闭环。

### 交付物

未来 `reports/P5-error-analysis.md`：至少 20 个可定位开发集样例、分组统计、实验登记、对照结果和方案选择记录。

### 验收标准

- 报告 OOV／词频／词长／标签／句长分组的样本量与错误率；至少列出一个有样本支持的主要失败群体。
- 对样例区分可由标签验证的错误与需要语言专家裁决的争议，后者不自行改金标准。
- 在改动前登记一条主假设，写出干预、预期改善群体和潜在退化。
- 监督模型与改进模型容量及训练预算匹配；字符编码消融与蒸馏按实际假设选择，不强制全部运行。
- 若采用蒸馏，教师输出仅来自训练集，记录教师与金标准分歧；硬标签／软概率方法如实命名，教师、学生词标签对齐。
- 改善必须在开发集与同规模监督对照比较；目标组与总体同时报告。有增益、无增益、退化三种结论均可完成该阶段。
- 冻结候选配置、三个随机种子、主资源指标、最终门槛和排除规则，之后再打开测试评分。

### 未通过处理

没有证据支持的错误假设不进入新实验。蒸馏无增益时可保留监督模型作为最终候选，并写明无增益；不制造“蒸馏成功”的叙述。

## 9. P6：最终评测与收益判定

### 目标

用冻结的配置判断压缩目标是否达成。

### 交付物

未来 `reports/P6-final-evaluation.md`、测试预测、逐种子指标、原始 benchmark、冻结配置与协议快照。

### 验收标准

- 最终候选和监督对照分别覆盖 3 个预登记种子；复用已有合格运行，不能按测试表现挑种子。
- 严格执行评测协议，所有运行有结果或有失败原因；报告总体、非标点、OOV、标签和资源表现。
- 报告正式门槛的逐项 `PASS`／`FAIL`／`INCONCLUSIVE`，不能只给总分。
- 达标标准：总体和非标点准确率平均损失均不超过 1 个百分点，且预选的延迟或内存目标达标；同时执行协议中的最差种子和 OOV 保护条件。
- 没达到或证据不足时，仍形成完整报告；不改测试标签、不在测试反馈后重新挑配置。
- 区分训练成本、教师成本与学生推理成本。

### 未通过处理

收益未达标则停止压缩宣传，进入失败实验交付。若测试暴露实现错误，修复后标记前次无效，写明测试已被观察，不能再声称后续是首次盲测。

## 10. P7：可复现的开源候选包

### 目标

让另一位开发者能得到相同预测与可解释的测量结果。

### 交付物

未来 README、锁定依赖、数据准备／训练／评测／推理入口、模型卡、许可与引用文件、结果清单及 `reports/P7-reproduction.md`。

### 验收标准

- 在新虚拟环境从零安装，获取固定模型，运行 JSONL 示例和批量评测；记录命令、退出码、耗时及输出。
- 相同权重的 CPU 预测与已发布报告对应结果一致；重新训练的复现允许种子波动，必须与报告范围比较。
- 首版推理入口支持 UTF-8、空 token 列表和 OOV；空列表输出空标签，非字符串 token、非法 JSON 或过长输入应给出明确错误及非零退出码，最大长度写入文档，不静默截断。
- 每条输出 tokens 原样保留、标签数相等、标签均属于固定 UPOS 集；右到左文本不手动反转。
- 有覆盖 CoNLL-U 解析、损失 masking、标签对齐及保存／加载的必要测试；不为无关模块扩大范围。
- 代码、数据、预训练资源与输出权重的许可分别说明；不能公开的产物提供获取／生成方法或标记未交付，不冒充完整权重发行。
- 不包含凭据、绝对私有路径、无关数据或虚构下载地址；推理可在模型准备完成后离线运行。
- 报告覆盖训练命令和配置；资源不足时，干净环境至少实测推理与评测，训练复现范围单独说明，不声称第三方已复现。

### 未通过处理

依赖／许可／权重缺失未解决时只称“发布候选”，不称完整可复用发行。公开发布不是本阶段验收前提。

## 11. P8：开源发布准备与求职展示

### 目标

把实验变成有证据的作品，清楚表达新增价值及限制。

### 交付物

未来 `reports/P8-portfolio.md`、发行说明候选、3–5 分钟演示流程、简历项目表述与结果链接清单。

### 验收标准

- 项目说明能回答问题、已有方法、自己的改动、效果、成本和限制；每个性能数字可追溯到 P6。
- 演示包含一次 CPU 推理和一张质量／资源对照表，不能只展示界面。
- 简历中的收益数字仅在实际达标后填写；未达标时展示诊断与实验结论，不写“实现低损压缩”。
- 发布候选包含代码／权重／文档及许可清单、哈希和复现入口；真实发布后另记录 URL、tag 和时间。
- 如需向现有项目提交问题或 PR，先有最小复现和必要测试；尚未提交、等待反馈、合并分别记录。
- 社区采用证据另列，可写“暂无”。没有外部反馈不影响求职材料准备完成，但不能宣称已验证需求。

### 未通过处理

证据不完整则修正文案或补材料；实际发布和对外沟通按后续授权执行，本轮不发布、不联系维护者。

## 12. 执行预算与依赖

保留原计划 400 元分配：训练 250、存储传输 50、预留 100；不代表当前授权支出。

- P0–P2 优先本地 CPU，不新增付费资源。
- P3 后在价格已核实且有授权上限的前提下，第一次远端短试跑至多分配 20 元；预计超出则先调整，不默认购买更大机器。
- 首轮探索最多 4 个正式配置（监督、一次容量调整、一次消融、一次蒸馏），无依据的分支不运行。
- 候选和监督对照各 3 个种子，已有运行计入；初始种子建议 13／42／2026，P5 冻结，可因实现约束提前修订。
- 预算分配包含既有运行，不重复相加。每次运行前计算剩余额度，预计成本含 25% 余量后仍须低于可用余额；不得自动动用预留或扩大授权金额。
- 环境准备完成后集中运行、及时同步产物，避免 GPU 等待开发。后台进程不等于实例停止计费，结束时记录平台实例状态。

P3 可以与 P4 本地实现交错，但正式训练必须先通过 P1、P2 和执行环境验收。P5 冻结后才进入 P6；完整实验路线的 P7 必须引用 P6 的实际结论。

## 13. 提前停止与阶段依赖例外

若 P1 数据不可用、P2 没有贡献空间，或后续耗尽预算，应写明停止阶段、证据、已经完成的工作和未完成项。后续模型阶段标为“未执行（因停止）”，不能标成通过或不适用来声称完整模型交付。

允许整理已完成的复现代码、诊断报告和求职材料，但此时 P7／P8 明确标为“部分交付”，引用实际停止报告；不要求制造 P6 测试结果，也不能称压缩项目已全部完成。后续恢复时从未通过的依赖开始，并核查已有产物，避免重复训练。
