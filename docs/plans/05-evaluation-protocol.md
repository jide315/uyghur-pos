# 评测与决策协议

更新日期：2026-11-13；版本：v0.2；状态：拟定，未执行。

用于 [阶段计划](04-phase-goals-and-acceptance.md) 的 P1–P7。以下是本项目的实验约定，不是已有实验结果或通用标准。P2 后、正式训练前可登记一次有依据的修订；P5 冻结最终快照，P6 不根据测试结果改门槛。

## 1. 比较对象与样本

- B0：按需加载、预分词输入的 Stanza 教师／部署基线。
- S0：字符编码＋小型 BiLSTM，使用人工标签监督训练。
- S1：依据 P5 假设完成的改进模型；若改进无效，可选择 S0 为最终候选。
- 可选消融：S0 去字符编码，或与 S1 相同容量／训练预算的无蒸馏对照。

每个对象固定软件、资源和训练来源。现成教师有额外预训练资源时披露其来源与体积；来源不明则不能称严格受控训练比较。若曾使用当前测试集训练，该权重不作为有效基线。

基线和学生输入同一整数词 ID 对应的 FORM 序列，评测 UPOS；忽略 CoNLL-U 区间和小数 ID，但保留原始文件供审计。输入不做未登记的 Unicode 替换、转写、字符反转或分词。空句、缺失标签、超长输入先报告处理规则，不允许模型单方跳过难例。

## 2. 数据隔离

- train：词表、字符表、频率和模型训练，教师输出也仅生成于此。
- dev：错误分析、早停、超参数、候选与硬件优化选择。
- test：结构／重复审计后封存；P5 冻结后才对最终模型和对照统一评分。

每个配置记录数据文件哈希；不使用 dev／test 扩展词表、学习分组阈值或生成训练伪标签。若公开预训练词向量等含有测试文本，披露可能污染，不把无法验证的来源描述为完全无泄漏。

## 3. 质量指标

`Accuracy = 正确 UPOS 数 / 有效整数 ID 词数`。

`非标点 Accuracy` 按 gold UPOS != PUNCT 选择词；OOV 指 FORM 不在 train 词表，大小写和 Unicode 处理沿用固定规则。

分组：OOV／已见词；频率 0、1、2–5、>=6；词长按训练集词类型的 Unicode 码点长度第 75 百分位定义长词（>= 该阈值）；句长 1–10、11–20、21–40、>=41。阈值在 P1 固定，字符长度不等于字节数或子词数。

每组报告 N、正确数与准确率；UPOS 各标签报告 precision／recall／F1、support，另报 macro-F1 作为诊断。分母为零的组显示 N/A，不填 0%。

开发错误样例按句 ID＋词 ID 定位，保存 gold、B0、S0、S1、词频和长度；样例不能代替全量分组统计。

## 4. 资源测量

主测平台为一台固定 CPU 主机，GPU 关闭。记录 CPU 型号、可用核数、内存、操作系统、Python／运行时版本、线程、量化／精度状态和后台负载。远端训练机器不是必须的 CPU 验收平台；两种机器的测量不能混为一组。

- 单句主测：batch=1、CPU 线程=1，计入 JSONL 解析、模型推理和输出序列化，不含首次模型加载。另可报告纯模型耗时，但不替代主测。
- 预热：按固定顺序取最多 30 个 dev 句，每模型同样处理。
- 正式延迟：完整评测切分每轮 1 遍，至少 3 轮；每轮交替模型顺序，保存逐句耗时，报告每轮 p50／p95 和总体 tokens/s。
- 冷启动：每模型 5 个新进程，计从启动到第一次有效输出时间。
- 内存：每模型 5 个新进程，对相同输入执行完整遍历，报告绝对峰值 RSS 中位数及范围；包含所有必要子进程，无关后台服务不计入模型进程。
- 空进程内存可作辅助，但 50% 门槛使用绝对峰值 RSS，不能用扣除基线后的数值夸大收益。
- 体积：列权重、词表／嵌入等必要资源字节数之和；完整环境体积另报，不能只列神经网络权重。

P2／P5 使用 dev 做测量和优化。P6 用 test 按同一协议验收。输入 ID、测量工具、原始数据和环境摘要必须保存。共享主机负载导致跨轮 p50 变异系数 >10% 时先重测；一次重测仍不稳定，资源结论为 INCONCLUSIVE，不挑最快一次。

## 5. 正式通过条件

以下条件在 P5 冻结，以三个固定种子的最终候选为对象，B0 结果固定。

### 质量条件，全部满足

1. 三种子总体准确率均值相对 B0 损失 <=1.0 个百分点。
2. 三种子非标点准确率均值相对 B0 损失 <=1.0 个百分点。
3. 最差种子总体准确率相对 B0 损失 <=1.5 个百分点。
4. 测试集 OOV 数 >=100 时，三种子 OOV 准确率均值相对 B0 损失 <=2.0 个百分点；少于 100 时列为证据不足，整体质量验收为 INCONCLUSIVE，不宣称未登录词稳健。

另列出 support>=100 且 F1 下降超过 5 个百分点的标签为风险。其用途是披露限制，不能隐藏在平均数中；是否成为额外硬门槛须在 P5 预先决定，不根据 test 临时豁免。

### 资源条件，预先选择一项主目标

P2 后选择并记录目标，P5 冻结；以下目标二选一：

- **延迟**：每个种子的三轮主测 p50 中位数，相对 B0 加速 >=2.0 倍，且三轮 p95 中位数不劣于 B0；B0 同样取三轮中位数。
- **内存**：每个种子的五次绝对峰值 RSS 中位数相对 B0 降低 >=50%。

两项都报告，但不能看到 test 后将未通过的主目标切换为另一项。内存主目标若以延迟明显上升换取，须显著披露，不描述为全面更优。模型体积单列，不单独替代质量＋主资源条件。

### 统计解释

逐种子报告分数、均值、标准差和正确数。以句子为抽样单位做配对 bootstrap（固定随机种子，1,000 次），报告总体与非标点准确率差的 95% 区间；每个种子独立计算，避免把同句三种子当独立样本。

点估计满足门槛但区间跨越质量边界时，只能说“本测试点估计达标，统计证据有限”，不能声称已证明一般性非劣效。区间无需被包装成正式非劣效检验。

### 三种结论

- PASS：质量与预选资源门槛通过、证据完整且资源测量稳定；区间不确定性按上述规则披露。
- FAIL：至少一项可测硬门槛未通过。
- INCONCLUSIVE：缺少必要种子、足够 OOV、可比基线或稳定测量等，无法完成验收。

判定顺序：已确认的硬门槛失败优先记 FAIL，并同时记录证据缺口；没有已确认失败但仍有必要证据缺口时记 INCONCLUSIVE；其余才为 PASS。

三种结论均可进入报告与候选包交付；只有 PASS 才能使用“达到本项目预设压缩门槛”。若统计区间仍跨质量边界，标题与摘要也必须保留点估计限制。

## 6. 预算、运行与重试

运行前登记 run ID、假设、配置哈希、数据哈希、种子、硬件、预计费用；运行后补结束状态、退出码、实付费用、产物及哈希。失败运行也入账。

同配置仅因明确环境／实现故障重试，记录原 run 和原因。没有增益不是故障，不支持无限重跑。先检查仍存活的任务及产物再判断重启，不因 SSH 断开直接重复启动。

主资源目标、候选与种子由 dev 决定；正式 test 后若修代码或改配置，应另建版本并说明测试已被观察，禁止在同一盲测记录里覆盖旧结果。

单个发行权重也应在测试前确定：默认从固定的三个种子中按 dev 非标点准确率最高选择，同分按种子数值较小者选择，记录 checkpoint 哈希；禁止按 test 挑选。仍需报告全部种子；发行权重自身的总体及非标点质量损失也都须 <=1.0 个百分点，并满足预选资源门槛，才能把三种子方案达标结论用于该发行模型。若整体均值达标而发行权重未达标，如实分别判定，不回头换另一个测试表现更好的种子。

## 7. 复现与公开声明

同权重、相同 CPU 环境要求预测一致；硬件不同可比较质量，不要求绝对耗时相同。报告中的资源提升只适用于记录的平台和设置。

代码能复现但性能未达标：称“完整实验／失败报告”。性能达标但没有独立使用证据：称“已验证工程收益的开源候选”。真实发布、外部复现和上游合并各自记录；不将计划、准备或本机复现当作第三方采用。
