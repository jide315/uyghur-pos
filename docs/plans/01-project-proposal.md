# 当前方案与边界

记录日期：2026-11-12

补充日期：2026-11-13；阶段目标和验收已扩展为 [P0–P8 计划](04-phase-goals-and-acceptance.md)，正式指标以 [评测协议](05-evaluation-protocol.md) 为准。

状态：根据对话固定的候选执行方案；可行性与贡献价值尚待基线实验验证。

## 1. 主题

**面向 CPU 部署的轻量维吾尔语词性标注——基于公开数据的模型压缩与误差评测。**

以现有维吾尔语模型为基线，训练小型词性标注模型，研究能否在准确率损失受控的条件下减少 CPU 推理延迟、内存占用或模型体积。

本项目不声称首次支持维吾尔语词性标注，也不把重新训练已有任务本身视作开源创新。

“几百元内”不包含尚未量化的个人开发工时。AutoDL 型号、显存及当前租赁价格需要在租卡前确认。

## 3. 任务范围

- 输入：已分词的维吾尔语句子。
- 输出：每个词的通用词性标签（UPOS）。
- 数据：UD Uyghur-UDT，采用固定版本及官方训练、开发、测试切分。
- 基线：Stanza 维吾尔语词性标注模型，采用相同的已分词输入。
- 学生模型：字符编码与小型 BiLSTM 词性标注器。
- 改进候选：知识蒸馏；仅在监督训练基线和错误分析完成后验证。
- 使用方式：CPU 命令行推理和批量评测。

首版不包含自动分词、句界识别、依存分析、大语言模型微调、ASR 或 OCR。预分词任务的准确率不能表述为原始文本端到端效果。

## 4. 贡献假设

### 求职价值

展示数据处理、实验对照、深度学习训练、模型压缩、CPU 部署及错误分析能力。核心证据是可复现的判断过程，而非仅有一份权重和演示页面。

### 开源价值

潜在受益者为需要在 CPU 或受限环境中运行维吾尔语基础 NLP 的开发者、研究者。这是待验证的使用者假设，尚无真实采用证据。

新增价值至少应满足以下一项，并保持任务质量可接受：

1. 相比现有基线显著降低 CPU 推理延迟。
2. 相比现有基线显著降低峰值内存或模型体积。
3. 找到现有工具的可复现问题，形成有依据的修复与回归测试。

单纯封装接口、重新上传已有数据、只与弱基线比较，均不足以证明上述价值。上游是否接受贡献、其他人是否采用模型，不能提前承诺。

## 5. 交付物

- 固定版本的数据准备脚本、来源说明与数据质量检查报告。
- 基线复现、监督训练、蒸馏实验及统一评测脚本。
- 允许发布的模型权重及模型说明。
- CPU 命令行推理工具与使用示例。
- 总体及分组质量、延迟、内存、体积、训练费用的实验报告。
- 已知限制、失败样例、复现命令与环境记录。

数据与代码的许可分别处理。公开可下载不自动等于允许重新分发；发布数据、衍生标注、教师输出和权重之前，检查各自许可及要求。当前仅记录计划，不预设所有产物均可公开。

## 6. 成功与停止原则

准确率与资源收益目标见 [实验计划](02-experiment-plan.md)。

首先做无需租卡的基线复现及部署测量。若现有模型已足够轻、没有合理压缩空间，或公平对照无法成立，则停止压缩方向并记录结论，不为完成项目名称而继续花钱训练。

没有母语者支持时，可依赖已有标签评测，但不能擅自修改语言学金标准、宣称纠正方言或推广到真实口语与其他领域。
